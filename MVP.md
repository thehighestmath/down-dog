# MVP: Yoga Training App — Ядро тренировки

> **Принцип:** Минимум кода, максимум проверки гипотезы. Без регистрации, без админки, без истории.
>
> Задачи MVP — в майлстоуне [v0.0.1a](https://github.com/thehighestmath/down-dog/milestone/1).
> Документ описывает, **что уже есть в коде** и **чего ещё нет**. Поменяли поведение — обновите и его.

---

## 1. Цель MVP

Проверить гипотезу: **нужен ли пользователям сервис персонализированных йога-тренировок с AI-подбором и озвучкой.**

**Критерии успеха:**

- Пользователь может создать тренировку за < 30 секунд
- Тренировка проходит без технических сбоев
- Пользователь возвращается хотя бы 1 раз

## 4. Архитектура (как сейчас)

Всё поднимается одной командой `docker compose up` (см. [README](README.md)).

```
                 Браузер
                    │ http://localhost:3000
                    ▼
┌──────────────────────────────────────────┐
│ frontend (nginx)                         │
│  • React SPA: настройки → плеер → финиш  │
│  • /api/* проксирует в backend           │
└──────────────────────────────────────────┘
                    │
                    ▼
┌──────────────────────────────────────────┐
│ backend (FastAPI, :8000)                 │
│  GET  /api/poses                         │
│  POST /api/workouts/generate             │
│  GET  /api/workouts/{id}                 │
│  • при старте применяет backend/sql/*.sql│
│  • тренировки хранит в памяти процесса   │
└──────────────────────────────────────────┘
          │                      │
          ▼                      ▼
┌──────────────────┐   ┌───────────────────────────┐
│ db (PostgreSQL)  │   │ minio (S3, :9000 / :9001) │
│  • poses (54)    │   │  • бакет down-dog         │
└──────────────────┘   │  • картинки из Images/    │
          ▲            │    заливает сервис s3     │
          │            └───────────────────────────┘
┌──────────────────┐
│ adminer (:8080)  │
└──────────────────┘
```

**Упрощения:**

- 1 бэкенд-сервис (не микросервисы)
- Нет аутентификации
- Нет Redis
- Миграции — сырые SQL-файлы без Alembic (переход — в v1.0.0, #18, #19)
- Сгенерированные тренировки живут только в памяти: после рестарта бэкенда `GET /api/workouts/{id}` вернёт 404

**Пока не подключено:** TTS (#5), раздача картинок из MinIO во фронтенд.

## 5. Модель данных (MVP)

Источник правды — [`backend/sql/`](backend/sql). Файлы применяются по алфавиту при каждом старте бэкенда, поэтому должны быть идемпотентными (`IF NOT EXISTS`, `ON CONFLICT`).

### Таблица: `poses`

```sql
CREATE TABLE IF NOT EXISTS poses (
    id SERIAL PRIMARY KEY,
    name_ru VARCHAR(255) NOT NULL,       -- "Поза собаки мордой вниз"
    name_sanskrit VARCHAR(255),          -- "Адхо Мукха Шванасана"
    name_en VARCHAR(255) UNIQUE,         -- "Downward-Facing Dog", по нему генератор ссылается на позу
    category VARCHAR(100),               -- warmup, mid, balancing, cooldown
    difficulty VARCHAR(50),              -- '1'..'5', хранится строкой
    focus_areas TEXT,                    -- 'спина, плечи, ноги' — через запятую, по-русски
    contraindications TEXT,              -- свободный текст
    description TEXT,
    image_url VARCHAR(512),              -- '/images/eagle.jpg'
    audio_url VARCHAR(512),              -- '/audio/eagle.mp3'
    hold_time_sec INTEGER,               -- удержание позы
    full_cycle_sec INTEGER               -- вход + удержание + выход, по нему считается время тренировки
);
```

### Seed-данные (54 позы)

| Категория   | Кол-во | Сложность |
| ----------- | ------ | --------- |
| `warmup`    | 9      | 1–2       |
| `mid`       | 20     | 2–4       |
| `balancing` | 10     | 2–4       |
| `cooldown`  | 15     | 1–4       |

Картинки лежат в [`Images/`](Images) (15 файлов с русскими именами) и не совпадают с `image_url` в сиде.

## 6. API (MVP)

Интерактивная документация — http://localhost:8000/docs.

### GET /api/poses

Каталог поз. Все фильтры необязательные.

**Query params:**

- `category` — точное совпадение (`warmup`, `mid`, `balancing`, `cooldown`)
- `difficulty` — точное совпадение сложности (1–5)
- `focus` — `back`, `neck`, `legs`, `full_body`, `relaxation` (как в генераторе, см. раздел 7)

**Response:**

```json
[
  {
    "id": 1,
    "name_ru": "Поза орла",
    "name_sanskrit": "Гарудасана",
    "name_en": "Eagle Pose",
    "category": "balancing",
    "difficulty": "4",
    "focus_areas": "плечи, верхняя часть спины, ноги",
    "contraindications": "Травмы коленей и лодыжек",
    "description": "Развивает баланс, укрепляет ноги и расправляет плечевой пояс.",
    "image_url": "/images/eagle.jpg",
    "audio_url": "/audio/eagle.mp3",
    "hold_time_sec": 20,
    "full_cycle_sec": 50
  }
]
```

### POST /api/workouts/generate

Сгенерировать тренировку.

**Request:**

```json
{
  "duration_min": 15,
  "level": "beginner",
  "focus": "back"
}
```

- `duration_min` — 5, 10, 15, 20 или 30
- `level` — `beginner`, `intermediate`, `advanced`
- `focus` — `back`, `neck`, `legs`, `full_body`, `relaxation`

Неверное значение → `400` с текстом ошибки в `detail`.

**Response:**

```json
{
  "id": "0b7c6f3e-…",
  "duration_min": 15,
  "level": "beginner",
  "focus": "back",
  "poses": ["Cat-Cow Pose", "Child's Pose", "Bridge Pose"]
}
```

`poses` — список `name_en` по порядку. Позы могут повторяться. Подробности о позе (картинку, длительность) фронтенд берёт из `GET /api/poses`. Если подходящих поз нет, список пустой.

### GET /api/workouts/{id}

Получить ранее сгенерированную тренировку (тот же формат). Нет такой → `404`.

## 7. Логика генератора (rule-based)

Код — [`backend/generator.py`](backend/generator.py), тесты — [`backend/generator_test.py`](backend/generator_test.py).

1. **Фильтр по фокусу.** `focus` переводится в русские ключевые слова, и остаются позы, у которых хотя бы одно слово есть в `focus_areas`:

   | `focus`      | Ключевые слова                                             |
   | ------------ | ---------------------------------------------------------- |
   | `back`       | спина, поясница, верхняя часть спины                       |
   | `neck`       | шея                                                        |
   | `legs`       | ноги, ягодицы, квадрицепсы, икры, задняя поверхность бедра |
   | `relaxation` | расслабление                                               |
   | `full_body`  | без фильтра                                                |

2. **План по уровню.** Время тренировки делится на доли, и каждая доля заполняется позами своей сложности:

   | `level`        | План                                                        |
   | -------------- | ----------------------------------------------------------- |
   | `beginner`     | 100% — сложность ≤ 2                                        |
   | `intermediate` | 1/3 — сложность ≤ 2, затем 2/3 — сложность 3                |
   | `advanced`     | 1/5 — сложность ≥ 4, 3/5 — сложность 3, 1/5 — сложность ≥ 4 |

3. **Заполнение доли.** Подходящие позы перемешиваются и берутся по очереди, пока хватает времени (`full_cycle_sec`). Повторы начинаются только когда исчерпаны все уникальные позы; одна и та же поза два раза подряд не ставится. Если очередная поза не влезает в остаток, ищется более короткая.

**Чего пока нет (F-11, F-12):** фаз «разминка → основная часть → заминка» по полю `category` и отдельного перехода в 5 секунд. Из-за этого у `advanced` нет ни разминки, ни заминки.

## 8. TTS-озвучка

В работе: #5. Договорились так:

1. Заранее сгенерировать набор фраз (≈16) через TTS-провайдер (ElevenLabs или Yandex SpeechKit).
2. Залить аудиофайлы в S3 (MinIO).
3. Бэкенд забирает аудио из S3 и отдаёт фронтенду.
4. Фронтенд проигрывает фразы по событиям таймера.

### Шаблоны инструкций

TTS_TEMPLATES = {

    "outro": "Тренировка завершена. Отдохните в Шавасане.",
